# Secrets para assinatura Android

Nomes preferenciais para este projeto:
- LISTA_COMPRAS_KEYSTORE_BASE64
- LISTA_COMPRAS_KEYSTORE_PASSWORD
- LISTA_COMPRAS_KEY_ALIAS
- LISTA_COMPRAS_KEY_PASSWORD

O workflow também aceita os nomes legados equivalentes LISTA_MERCADO_* (fallback), além dos aliases ANDROID_*, KEYSTORE_* e SIGNING_* já suportados. O arquivo de keystore e as senhas reais não são fornecidos aqui nem foram alterados. Não armazene chaves no repositório.

## Comportamento do GitHub Actions a partir de 1.0.37+41

- **Sem Secrets:** o build (Kotlin, testes, APK Debug e Android Lint) permanece verde. O APK Debug está disponível na aba **Artifacts** da execução, por 30 dias; não é publicada GitHub Release.
- **Com quatro Secrets válidos:** o workflow valida keystore e alias, gera Release assinada e só então publica no GitHub Releases.
- **Com Secrets parciais:** não mistura campos de conjuntos diferentes. Publica apenas o Debug nos Artifacts, com aviso de configuração incompleta.
- **Com keystore incorreta:** a etapa de assinatura falha explicitamente, sem publicar uma falsa Release.

É obrigatório fornecer os **quatro** valores de um mesmo grupo:

```text
LISTA_COMPRAS_KEYSTORE_BASE64=<base64 real do arquivo .jks/.p12 em uma linha>
LISTA_COMPRAS_KEYSTORE_PASSWORD=<senha real>
LISTA_COMPRAS_KEY_ALIAS=<alias real>
LISTA_COMPRAS_KEY_PASSWORD=<senha real da chave>
```

Use **Repositório > Secrets > Importar** no GitHub Manager (ou Settings > Secrets and variables > Actions no GitHub). Não envie o arquivo com valores reais para chats, commits, issues ou GitHub Drive público. Nunca coloque a keystore no repositório. Use um backup privado e durável da chave de assinatura: perdê-la pode impedir atualização de APKs já instalados com a mesma assinatura.

Um APK Debug utiliza a assinatura de depuração do executor, que não é uma identidade de publicação estável e pode exigir desinstalação em uma atualização futura.
